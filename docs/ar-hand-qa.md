# 空間固定・手操作AR 改修記録（v0.8.1）

## 目的

iPhoneのSafariなどで配管を空間内に固定し、手のジェスチャーでバルブ開度を操作する実験版の安定性を改善する。実際の壁内配管を検知する機能ではない。

## 改善内容

- MediaPipeから取得した正規化座標を、カメラ映像のアスペクト比・画面の切り抜きを考慮してCSSピクセルへ変換する `hand-screen-map.js` を追加。
- カメラ表示の向きがSDK・端末により異なる場合は、実機で目印を照合し、左右反転・90度回転・180度回転の補正を手動選択できる。初期値「標準」が常に正確とは限らない。
- SLAMの`NORMAL`が連続10フレーム続いてから配置を有効化し、連続3フレームの非`NORMAL`で操作を止める。SDKの追跡精度そのものは改善できない。
- V-01〜V-03を3Dスプライトとして表示する。再生成時はジオメトリ・マテリアル・CanvasTextureを破棄する。
- スマホの操作パネルを開かずにAR開始と配置ができるフローティング操作ボタンを追加。
- 手認識・空間追跡の状態を独立して検証できるNodeテストを追加。既存の配管計算・ジェスチャーテストも維持。

## 実機検証が必要な点

1. Safariのカメラ許可後、8th Wallが`NORMAL`へ移るか。
2. 手の目印が正しく重なるか（映像の切り抜き・向き・鏡像の補正を含む）。
3. 配置後にスマホを動かしても配管位置が保たれるか。
4. 手を回転したときに違うバルブが誤反応しないか。
5. CPU/GPU負荷、端末の発熱、バッテリー消費。

## 技術的制限

- バルブとの接触は画面座標による近似であり、3Dの手・物体接触判定ではない。
- 仮想配管の配置位置はカメラからの推定距離を使う。壁面の自動検出や実物の建物配管検出ではない。
- iPhoneのQuick Lookを操作する方式ではなく、8th Wall + Three.js + MediaPipeを同一Web AR画面で使う実験版。
- 手の正規化座標から表示座標への変換は、カメラ背景の`cover`相当を前提とする。実機の映像変換と異なれば手動補正か追加の調整が必要。
- 8th WallはSLAMを含むバイナリ配布版を使用しており、完全なMITオープンソースではない。ライセンス条件は別途確認する。
- ブラウザによりカメラ・手認識が動かない場合は、タップやスライダーを代替操作とする。

## ローカル自動テスト

`node tests/ar-hand.test.cjs && node tests/hand-screen-map.test.cjs && node tests/piping.test.cjs && node tests/gesture.test.cjs`

GitHub Actions `ar-hand-qa.yml`でも同等のテストを実行する。これらは実機AR動作の証明にはならない。

## v0.8.2 — AR優先の画面と負荷・復帰対策

- `index.html` は一体型ARの入口とし、従来の2Dカメラ重ね合わせデモをメイン導線から外した。従来機能は `legacy-demo.html` に退避。
- 手認識モデルはARカメラ起動時ではなく、3D配管を空間に配置した後に非同期初期化する。通信・推論によりARの初回起動を妨げないようにする。
- 手認識に失敗してもタップとスライダーで操作でき、手認識の再試行ボタンを利用できる。
- 非表示から復帰したとき、保持していたピンチ操作を破棄して誤操作を防ぐ。
- 接合部の球体をノードごとに重複生成せず、共有ジオメトリを再利用。再生成時の3D資源解放は同一ジオメトリを一度だけ行う。
- `tests/entrypoint.test.cjs` でAR優先の導線を検証する。
- 8th Wallの`onAttach`で動画要素が渡される仕様、および`processCpuResult.reality.trackingStatus`を確認して実装。実機によるSDKの正常動作の検証は別途必要。

**実機未検証事項:** iOS SafariでのSLAM追跡、MediaPipeの手座標一致、XR8エンジンの動画描画、パフォーマンス・発熱。自動テスト合格はこれらの動作保証ではない。
