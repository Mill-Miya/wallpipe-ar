# 用途別配管生成の設計判断（v0.9.7）

## 1. 共通仕様

- すべての管路を水平・垂直線分で構成し、接続点をノード、管路をエッジとして管理する。
- 用途ごとの接続規則を固定したうえで、設備や分岐の経路パターンを種（seed）に応じて選択する。座標の微小な揺らぎだけに依存しない。
- 給水と空調は3系統、工場は2〜5系統を生成する。各系統の可動バルブは、その系統だけを遮断する。閉じたバルブを迂回する無意味な配管を設けない。
- 見た目の管径を主管・枝管・戻り管で変える。ただし管径は模式表示のパラメータであり、実製品の呼び径を表さない。

## 2. 用途別の接続規則

- **給水**: 供給源から主管を通し、使用設備に3本の枝管を分岐させる。各枝管に止水弁を設置。枝管末端は直結またはエルボを含むオフセット経路から選び、使用設備の位置と管路長を変える。
- **空調**: 往き主管と戻り主管の間に3つのコイル回路を並列接続。コイルの横位置を変え、往き・戻りともエルボを含む取り回しを生成する。各回路は独立した流量調節弁を持つ。
- **工場**: 入口・出口のマニホールド間に2〜5本の独立したプロセスラインを生成する。直結・弁位置オフセット・設備オフセット・複合オフセットをライン単位で選択する。仕切弁・ボール弁・バタフライ弁・調節弁から種類を選び、管径・分岐数・6種類の配色とともに変化させる。弁の接続面間寸法はGLBの軸方向長さを調整して一致させる。

## 3. 表示する流れ

- 供給源の節点に無次元ポテンシャル1、末端の節点に0を設定する。
- 管路に長さ・見かけの径から擬似抵抗を与え、各内部接続点での収支がゼロになる連立一次方程式を解く。
- 各管路の流れは両端のポテンシャル差を抵抗で割って算出する。絶対流量の単位はなく、非線形の損失、局部抵抗、ポンプ曲線等は扱わない。
- 各末端・設備ラインの流れがあるかを確認し、UIでは「3系統中2系統が通水中」のように示す。
- 流れの矢印は接続された管路の計算結果に沿って向きを変える。

## 4. 現実との相違

- 建物の実配管、壁厚、配管支持、保温、保守空間、消防・衛生設備の規制、分岐継手の品種などは再現しない。
- 流体抵抗の式は教育用の電気回路アナロジーであり、圧力損失と正確に同じではない。
- 方向センサによる「壁・床・天井」の区別はカメラ光軸の大まかな推定だけであり、実際の壁面形状・階数・地盤高は判定できない。
- AR/3Dプレビューには自動生成ネットワークから、曲面の継手・中空配管・各種弁を配置する。これは設備配置の教育用表現であり、製品規格や現実の圧力損失計算に適合するものではない。

## 5. 検証

`node tests/piping.test.cjs` にて、3種類の設備×3種類の観察面×180シード×8通りのバルブ状態（12,960ケース）を検証。追加で `tests/full-scan.test.cjs`（10,845件のネットワーク、43,380件の流量状態）、`tests/system-diversity.test.cjs` と `tests/factory-valve-variation.test.cjs` により、種の再現性、経路トポロジーの変化、弁の配置順、遮断時の流量と接続長の整合性を検証。流れの連続性、閉止系統の流量ゼロ、供給総量と末端総量の一致、直交線分のみで構成されることを検査する。
## 6. 工場モード特有の描画不具合と再発防止

- 旧実装ではマニホールド中心付近に、同じ方向に向いた配管ポートを複数作っていた。継手の向きの計算で線形独立な2方向を得られず、Three.jsの3D配置時にエラーとなる構造だった。
- **修正:** y=0を必ず含む単一の縦主管上に分岐点を配置し、既存点を再使用する。中心部には重複する施工ノードや同一方向の重複ポートを生成しない。
- 継手の生成段階で、2方向の行列式が0に近い不正なエルボ・T字・十字接続を検出したら、節点番号付きエラーを出す。
- 旧エラー表示はすべて通信障害のように案内していたが、新しい3Dプレビューでは配管生成・GLB生成・バルブ読み込みの段階とseed・実際のエラー理由を示す。
- 乱数の最初の出力が小さい連番シードへ偏るため、工場の系統数を決める前に生成器を3回更新する。これにより小さいシード値でも2〜5本の系統を生成できる。
- 給水と空調は3系統を維持し、工場のみ可変系統数とする。ARの選択欄と開度配列は固定3件ではなく、生成されたバルブ数に対応する。
