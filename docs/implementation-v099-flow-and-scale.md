# WallPipe AR v0.9.9｜流体表現と観察サイズ 改修指示書

作成日：2026-11-12 / 対象リポジトリ：`Mill-Miya/wallpipe-ar`

## 目的
iPhone上の実機報告に基づき、給水モードで最後のバルブ付近しか水流を確認できない問題を解消する。バルブ単位で独立した流量表示を実装し、水を視認しやすい棒状の流れで表現する。近接探索時の3D設備をもう少し大きく表示する。

## 実装要件
1. **各末端の独立した吐水演出**：`network.terminals` の件数から描画物を生成し、表示／長さ／太さ／速度を `solveFlow(...).terminalFlows[i]` に対応づける。固定の末端インデックスや「最後の要素」参照は使わない。
2. **全開／半開／全閉**：全開なら各末端から表示。1系統だけ閉じると該当する吐水だけ停止し、他は維持。半開なら流れが弱くなる。0流量やモデル未配置時に水が出ない。
3. **バー型の水流**：配管出口付近に半透明の水柱と、流れ方向に移動する細いハイライトを表示する。必要な範囲で3D奥行き・サイズを維持し、過剰な発光・大量の粒子・依存ライブラリ追加を避ける。
4. **配管内部の流れの可視化**：管の中に埋もれて見えない球体マーカーだけに依存せず、流路に沿って移動する短いバーを視認できる位置に配置する。実際の流量を示す教育用表示であり、実物の水の透明度を再現するものではない。
5. **拡大表示**：近距離探索の初期倍率を165%から185%へ上げ、設定上限を260%へ拡張。「全体を確認」プリセットは既存倍率を維持。
6. **既存機能の維持**：給水・空調・工場、ランダム生成、GLB配管・バルブ、手認識、深度マスク、空間追跡、流路計算、タップ・スライダー操作を破壊しない。

## 実装方法
- 流量計算 `js/piping-engine.js` は原則変更せず、`js/flow-visuals.js` に「terminalごとの位置・値・状態」の決定と3D表示を分離。
- 既存 `js/ar-hand.js` の `buildNetwork`, `refreshFlow`, `animateFlow` に統合。再生成時・セッション停止時に描画物を解放。
- 吐水と流路バーの位置は実際のネットワーク節点・エッジをもとに求める。全モードの可変バルブ数にも追随。
- 水柱は現実の質量流量を物理的に再現したものではなく、相対流量の可視化として明示。

## 完了条件と検証
- 給水の3末端で、全開・全閉・任意1系統閉・半開・再生成の結果が個別に正しく反映。
- 空調3系統・工場2〜5系統でも独立表示が破綻しない。
- JavaScript構文、流量・吐水対応テスト、既存のAR・3D回帰テスト、GitHub Actionsが成功。
- 可能なら実ChromiumのWebGLブラウザテストで表示／再生成を確認。
- **iPhone実機の描画・手の深度遮蔽・空間固定は、自動テストのみでは合格扱いにしない。**
