## v0.5 の主な機能

- **用途別の配管生成**: `js/piping-engine.js` が給水・空調冷温水・工場設備の3種類の配管を、それぞれ別の接続規則で生成します。位置・長さ・機器の並びを乱数で変えますが、無意味な接続やバルブの迂回路は生成しません。
  - **給水**: 給水引込 → 主管 → 3つの使用設備（洗面・トイレ等）への枝管。各設備の手前に個別止水弁を配置。
  - **空調冷温水**: 往き管・戻り管と3台の空調コイルを持つ並列回路（ダイレクトリターン方式の模式例）。各コイル入口に調節弁を配置。
  - **工場設備**: 共通入口・出口のマニホールドと3つの独立した設備ライン。各ラインに遮断弁を配置。
- **バルブ操作と流れの整合性**: 各バルブの状態を反映して、枝管・各回路の流れを再計算します。止めた系統には流れが表示されず、別の系統が開いていれば通水を続けます。
- **配管の透視演出**: 画面タップから模式図が現れます。新しい場所をタップすると新しい配置を生成します。繰り返し訪問した位置を同定する機能はありません。
- **観察面の切替**: 壁・床下・天井裏を手動指定。対応端末では方向センサからの大まかな自動切替を試せます。端末の姿勢であって建物の構造判定ではありません。
- **階・高度**: 階数は手動指定。GPS高度と精度はボタン操作後の参考表示のみで、階数を自動判定しません。
- **2Dカメラ合成**、流れのON/OFF、透過度・倍率・位置調整、キーボード操作、スマホ収納式パネルに対応。

## 重要な制約

- 配管の位置・構造は**シミュレーション上の架空のもの**です。カメラが実際の配管を検出するわけではなく、実際の建築設備図面も使っていません。
- 流れの計算は管長・管径から設定した抵抗を使う**簡略化した線形ネットワークモデル**です。単位付きの実流量、圧力、損失水頭、ポンプ特性、流体の温度・粘度などは計算しません。設計・点検・保安判断には使用できません。
- **3D / ARモードは従来の固定サンプル**です。2Dの自動生成された配管、流路計算、タップ座標とは連動しません。
- 2Dカメラ合成では配管を画面に重ねるだけで、壁面への空間固定はできません。
- カメラ映像・位置情報を独自バックエンドへ送信するコードはありません。端末・ブラウザによる許可処理や測位基盤の通信は別です。

## v0.7 手でバルブを操作する実験

[手操作デモを開く](https://mill-miya.github.io/wallpipe-ar/gesture-test.html)

- 指先をバルブの位置に合わせてピンチし、手の向きを回転させると**開度0〜100%**を変更できます。手を開いて約1.4秒かざすと全開／全閉が切り替わります。
- MediaPipe Hand Landmarkerを利用した**通常のカメラ合成**です。背面カメラを標準とし、前面カメラにも切り替えられます。初回のモデル取得にはインターネット接続が必要です。
- カメラや認識モデルが使えなくても、タップ・開度スライダー・全開／全閉ボタンで操作できます。
- 配管計算は開度を0〜1の数値で受け取り、バルブの抵抗を近似変更します。従来の真偽値による開閉操作は互換性を維持します。計算結果は実際の流量ではありません。
- **iOSのAR Quick Look空間固定機能とは未統合です。** このページは手の認識とバルブ操作の検証用であり、3Dモデルが壁に固定されるわけではありません。
- カメラ映像はブラウザ内で認識処理され、アプリ独自のサーバーに送信しません。モデルの取得先には通常のネットワークアクセスが発生します。

検証: `node tests/piping.test.cjs` と `node tests/gesture.test.cjs` を実行してください。手の検出精度とSafari実機のカメラ動作は未確認です。

## 空間固定AR × 手操作（試験版）

[一体型ARを起動する](./ar-hand.html)（公開URL： https://mill-miya.github.io/wallpipe-ar/ar-hand.html ）

- 8th Wall XR Engine Binary（SLAM）とThree.jsで配管をワールド座標に配置。配置後は画面座標へ張り付けず、端末の移動に応じて視点が変わります。
- 同一の8th Wallカメラ映像をMediaPipe Hand Landmarkerで処理し、ピンチ＋手の回転、または手をかざす操作を判定。画面上に投影したバルブ位置を使う**2D近接判定**であり、奥行きの接触検出ではありません。
- バルブ開度は0〜100%で既存の配管ネットワーク計算に反映。手認識が不安定な場合は画面タップ・スライダー操作を使用できます。
- 現実の壁面は自動検出しません。カメラ前方およそ1.5mを仮想配置の基準として推定し、以後は固定したワールド座標を使用します。追跡喪失やスケール推定誤差でズレる可能性があります。
- 端末のカメラとARエンジンに許可・対応が必要です。**iPhone実機におけるSLAM、手認識、位置合わせ、パフォーマンスは未検証**です。カメラ映像のアプリ独自バックエンド送信処理はありませんが、外部SDKと手認識モデルを読み込みます。
- 8th Wall Engine BinaryはMIT版とは異なる**バイナリ専用ライセンス**です。ソースコードに改変・再配布されていないCDN版を使用しています。詳細は[公式ライセンス](https://github.com/8thwall/engine/blob/main/LICENSE)を参照してください。

新設ファイル：`ar-hand.html`、`js/ar-hand.js`、`tests/ar-hand.test.cjs`、`.github/workflows/ar-hand-qa.yml`。以前の2DデモとQuick Lookの空間固定テストは維持しています。
