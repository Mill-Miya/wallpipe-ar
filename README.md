# WallPipe AR — 開発状況

## v0.8.4｜iPhone実機からの不具合報告への対策（2026-11-11）

- **手操作の可視化:** AR画面内に手認識の状態を常時表示。未読込・読み込み失敗・手未検出・かざし中・回転操作中・追跡喪失を区別。
- **手認識の安定化:** 8th Wallが提供するカメラ映像を利用し、video要素がない場合のみ同じMediaStreamから代替videoを準備。端末によって動画時刻が更新されない場合でも検出ループを止めず、処理間隔を約195ms以上に制限。
- **対象バルブ判定:** 画面投影位置の近接許容範囲を拡張。これは2D推定であり、実際の手とバルブの3D接触検出ではありません。不要な誤認識に注意。
- **初期配置:** 推定距離を2.2mに拡大し、モデルの初期倍率を72%に変更。距離・高さ・倍率は配置前に調整可能。配置後は同じワールド座標を保持。
- **表示:** AR視野を塞ぎやすかったバルブラベルを小型化。
- **重要:** 8th Wallのワールドトラッキングは床など水平面に基づき、壁の垂直面を直接検出しません。壁への位置合わせはユーザーの推定配置であり、スケールや追跡のドリフトは残り得ます。詳細: https://8thwall.org/docs/troubleshooting/world-tracking-issues
- **検証範囲:** GitHub ActionsでJavaScript構文、配管計算、ジェスチャー制御、UI配置の契約チェックを実施。実際のiPhoneで手が認識されるか、追跡が安定するかは再検証が必要。

公開URL: https://mill-miya.github.io/wallpipe-ar/ar-hand.html


## v0.8.3｜iPhoneでの表示不具合への対応（2026-11-11）

- **カメラ全画面化:** 8th Wall公式の `XRExtras.FullWindowCanvas.pipelineModule()` を追加。左上の一部にだけ映像が出る問題への修正。ただしiPhone実機での再確認は未実施。
- **追跡状況:** `NORMAL`／`LIMITED`、初期化理由を画面に示し、空間認識のやり直し操作を追加。
- **配置補正:** 壁は自動検出していない。カメラの向きに対し推定距離0.7–2.5m、高さ±0.6mで位置を指定してワールド座標へ配置する。配置後は距離調整操作をロック。
- **3D造形:** 管径による太さ、継手・フランジ、支持金具、レバー式ボール弁・手回し調節/仕切弁・バタフライ弁を表示。工事図面や製品設計図に基づく精密モデルではない。
- **利用上の制約:** 空間追跡は特徴の少ない壁で安定しないことがある。上手くいかなければ `spatial-test.html` のOS純正AR配置を試せるが、そこでは手認識による操作はできない。
- **検証:** GitHub ActionsによるJavaScript静的・配管計算・ジェスチャー・XR連携契約のテスト。**実機での空間固定、正しいカメラサイズ、ジェスチャー精度は未検証**。

# WallPipe AR — 配管可視化シミュレーター

**現在のメイン体験は一体型Web AR（v0.8.4）です。** 8th Wallによる空間追跡で仮想の3D配管を配置し、同じカメラ映像を用いた手の認識でバルブ開度を変更する実験アプリです。実際の壁内部や配管は検出しません。

- **[WallPipe AR の入口](https://mill-miya.github.io/wallpipe-ar/)** — 一体型ARの起動手順。
- **[空間固定＋手操作AR](https://mill-miya.github.io/wallpipe-ar/ar-hand.html)** — 現行の開発対象。
- 従来の「カメラ映像に2D配管を重ねる」方式は主要画面から外し、`legacy-demo.html` に退避しています。新しいAR体験と取り違えないよう、入口からはリンクしていません。
- 手認識は配置後に読み込みます。読み込みに失敗してもタップ・スライダーで操作でき、再試行できます。
- iPhone実機での空間固定精度・手との位置合わせは未検証であり、コード・自動テストの成功は実機動作の保証ではありません。

以下は開発の履歴と技術資料です。

## v0.6 — 空間固定・視差テスト（iPhone Safari向け）

- [空間固定テストを開く](https://mill-miya.github.io/wallpipe-ar/spatial-test.html)
- 配管の3D模型を、カメラ映像に重ねる2Dレイヤーではなく、**AR Quick Look / WebXR の空間追跡環境**で配置する実験です。
- 壁基準の枠（約1.6m×1.0m）と、壁に対する奥行きが異なる配管を含むGLBモデルを用意しました。実物大を意図した寸法で、横へ移動した際の視差・側面表示を検証します。
- WebXR対応機器では壁面配置モードを要求します。iPhoneのSafariでは**AR Quick Look**が空間配置を担当します。壁への自動配置は強制できない場合があるため、**ユーザーが壁の近くにモデルを移動・配置する**必要があります。壁の検出に失敗した際は床に置かれる場合もあります。
- **配置した位置の保持はARセッション中のみ。** 一度閉じたセッションの位置を保存したり、次回も同じ場所に復元したりする機能はありません。
- 実物の配管を検出したり、壁の内部を透視しているわけではありません。立体モデルが壁の手前に配置され、隠れた配管のように見えるかを検証する段階です。
- 現段階ではモデル1種類の追従確認を優先しています。2D配管の自動生成・バルブ開閉・流体計算は**別モードとして維持**し、AR空間内でのバルブ操作には未対応です。
- 動作確認：生成モデルのGLB構造・奥行き寸法、GitHub上の自動生成成功。iPhone実機での空間追跡精度・壁への配置成功は未検証。

## v0.5 の主な機能

- **用途別の配管生成**: `js/piping-engine.js` が給水・空調冷温水・工場設備の3種類の配管を、それぞれ別の接続規則で生成します。位置・長さ・機器の並びを乱数で変えますが、無意味な接続やバルブの迂回路は生成しません。
  - **給水**: 給水引込 → 主管 → 3つの使用設備（洗面・トイレ等）への枝管。各設備の手前に個別止水弁を配置。
  - **空調冷温水**: 往き管・戻り管と3台の空調コイルを持つ並列回路（ダイレクトリターン方式の模式例）。各コイル入口に調節弁を配置。
  - **工場設備**: 共通入口・出口のマニホールドと3つの独立した設備ライン。各ラインに遮断弁を配置。
- **バルブ操作と流れの整合性**: 各バルブの状態を反映して、枝管・各回路の流れを再計算します。止めた系統には流れが表示されず、別の系統が開いていれば通水を続けます。
- **配管の透視演出**: 画面タップから模式図が現れます。新しい場所をタップすると新しい配置を生成します。繰り返し訪問した位置を同定する機能はありません。
- **観察面の切替**: 壁・床下・天井裏を手動指定。対応端末では方向センサからの大まかな自動切替を試せます。端末の姿勢であって建物の構造判定ではありません。
- **階・高度**: 階数は手動指定。GPS高度と精度はボタン操作後の参考表示のみで、階数を自動判定しません。
- **2Dカメラ合成**、流れのON/OFF、透過度・倍率・位置調整、キーボード操作、スマホ収納式パネルに対応。

## 重要な制約

- 配管の位置・構造は**シミュレーション上の架空のもの**です。カメラが実際の配管を検出するわけではなく、実際の建築設備図面も使っていません。
- 流れの計算は管長・管径から設定した抵抗を使う**簡略化した線形ネットワークモデル**です。単位付きの実流量、圧力、損失水頭、ポンプ特性、流体の温度・粘度などは計算しません。設計・点検・保安判断には使用できません。
- **3D / ARモードは従来の固定サンプル**です。2Dの自動生成された配管、流路計算、タップ座標とは連動しません。
- 2Dカメラ合成では配管を画面に重ねるだけで、壁面への空間固定はできません。
- カメラ映像・位置情報を独自バックエンドへ送信するコードはありません。端末・ブラウザによる許可処理や測位基盤の通信は別です。

## v0.7 手でバルブを操作する実験

[手操作デモを開く](https://mill-miya.github.io/wallpipe-ar/gesture-test.html)

- 指先をバルブの位置に合わせてピンチし、手の向きを回転させると**開度0〜100%**を変更できます。手を開いて約1.4秒かざすと全開／全閉が切り替わります。
- MediaPipe Hand Landmarkerを利用した**通常のカメラ合成**です。背面カメラを標準とし、前面カメラにも切り替えられます。初回のモデル取得にはインターネット接続が必要です。
- カメラや認識モデルが使えなくても、タップ・開度スライダー・全開／全閉ボタンで操作できます。
- 配管計算は開度を0〜1の数値で受け取り、バルブの抵抗を近似変更します。従来の真偽値による開閉操作は互換性を維持します。計算結果は実際の流量ではありません。
- **iOSのAR Quick Look空間固定機能とは未統合です。** このページは手の認識とバルブ操作の検証用であり、3Dモデルが壁に固定されるわけではありません。
- カメラ映像はブラウザ内で認識処理され、アプリ独自のサーバーに送信しません。モデルの取得先には通常のネットワークアクセスが発生します。

検証: `node tests/piping.test.cjs` と `node tests/gesture.test.cjs` を実行してください。手の検出精度とSafari実機のカメラ動作は未確認です。

## 空間固定AR × 手操作（試験版）

[一体型ARを起動する](./ar-hand.html)（公開URL： https://mill-miya.github.io/wallpipe-ar/ar-hand.html ）

- 8th Wall XR Engine Binary（SLAM）とThree.jsで配管をワールド座標に配置。配置後は画面座標へ張り付けず、端末の移動に応じて視点が変わります。
- 同一の8th Wallカメラ映像をMediaPipe Hand Landmarkerで処理し、ピンチ＋手の回転、または手をかざす操作を判定。画面上に投影したバルブ位置を使う**2D近接判定**であり、奥行きの接触検出ではありません。
- バルブ開度は0〜100%で既存の配管ネットワーク計算に反映。手認識が不安定な場合は画面タップ・スライダー操作を使用できます。
- 現実の壁面は自動検出しません。カメラ前方およそ1.5mを仮想配置の基準として推定し、以後は固定したワールド座標を使用します。追跡喪失やスケール推定誤差でズレる可能性があります。
- 端末のカメラとARエンジンに許可・対応が必要です。**iPhone実機におけるSLAM、手認識、位置合わせ、パフォーマンスは未検証**です。カメラ映像のアプリ独自バックエンド送信処理はありませんが、外部SDKと手認識モデルを読み込みます。
- 8th Wall Engine BinaryはMIT版とは異なる**バイナリ専用ライセンス**です。ソースコードに改変・再配布されていないCDN版を使用しています。詳細は[公式ライセンス](https://github.com/8thwall/engine/blob/main/LICENSE)を参照してください。

新設ファイル：`ar-hand.html`、`js/ar-hand.js`、`tests/ar-hand.test.cjs`、`.github/workflows/ar-hand-qa.yml`。以前の2DデモとQuick Lookの空間固定テストは維持しています。
